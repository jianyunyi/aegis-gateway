## 1. 概述

AEGIS 是统一的企业大模型接入网关。业务方（下游调用方）通过 AEGIS 接入多家大模型，获得统一鉴权、限流、计费、观测与评测能力。

## 2. 用户角色（Persona）

| 角色 | 描述 | 核心诉求 |
|---|---|---|
| **调用方开发者** | 各业务线接入 AI 能力的后端工程师 | 接入简单、稳定、文档清晰、出问题能查 |
| **平台管理员** | 技术负责人 / 网关 Owner（本项目即本人） | 成本可控、安全、可观测、可评测 |
| **审计者** | 财务 / 安全（演示角色） | 账单清晰、Key 安全、日志可追溯 |

## 3. 功能需求（Epic → 用户故事 → 验收标准）

### Epic-1 统一接入（MUST）

| 用户故事 | 优先级 | 验收标准（AC） |
|---|---|---|
| 作为调用方，我希望用 OpenAI SDK 直接调用网关，不改业务代码 | MUST | 任意 OpenAI 兼容 SDK 改 `base_url` 指向网关即可完成对话 |
| 作为调用方，我希望支持流式输出，逐字返回 | MUST | SSE 流式返回；首字延迟（TTFT）被记录；断连可感知 |
| 作为调用方，我希望了解网关支持哪些模型 | MUST | `GET /v1/models` 返回可用模型列表 |
| 作为调用方，我希望网关把多提供商差异屏蔽掉 | MUST | 同一 OpenAI 协议访问 DeepSeek/OpenAI/Ollama，无需感知差异 |

### Epic-2 API Key 与配额管理（MUST）

| 用户故事 | 优先级 | 验收标准（AC） |
|---|---|---|
| 作为管理员，我希望创建/吊销 Key | MUST | 生成 `ak_` 开头 Key；DB 只存 SHA-256 哈希；吊销即时生效 |
| 作为管理员，我希望给 Key 设配额与有效期 | MUST | 配额超限/过期返回 429，提示明确 |
| 作为调用方，我希望用 Key 鉴权 | MUST | 无 Key/错误 Key 返回 401；不泄露 Key 信息 |

### Epic-3 限流与防滥用（MUST）

| 用户故事 | 优先级 | 验收标准（AC） |
|---|---|---|
| 作为管理员，我希望按 Key 限流 | MUST | 令牌桶：key 级 RPS 限制，超限 429 |
| 作为管理员，我希望全局防刷 | SHOULD | 全局滑动窗口：异常流量自动拦截并告警 |
| 作为管理员，我希望限流参数可配置 | SHOULD | 每 Key 可配 rps / burst；热更新生效 |

### Epic-4 计费与对账（SHOULD）

| 用户故事 | 优先级 | 验收标准（AC） |
|---|---|---|
| 作为审计者，我希望每次调用按 token 计费 | SHOULD | 按模型单价 × 实际 token 计价，精确到 0.000001 元 |
| 作为审计者，我希望看每日账单 | SHOULD | 日汇总表：请求数 / token / 成本，支持按 Key 与模型下钻 |
| 作为管理员，我希望对账一致 | SHOULD | 先扣后结 + 定时对账补偿，Redis 扣减与 MySQL 流水最终一致 |

### Epic-5 可观测（SHOULD）

| 用户故事 | 优先级 | 验收标准（AC） |
|---|---|---|
| 作为管理员，我希望查任意一次调用 | MUST | 全量日志：请求 ID、Key、模型、token、成本、延迟、状态 |
| 作为管理员，我希望看实时大盘 | SHOULD | 今日请求量 / 成本 / token / 成功率 / 平均延迟 |
| 作为管理员，我希望看趋势图 | SHOULD | 7/30 天趋势：请求、成本、延迟分位数、错误分布 |

### Epic-6 成本优化三件套（SHOULD）

| 用户故事 | 优先级 | 验收标准（AC） |
|---|---|---|
| 作为管理员，我希望简单任务走便宜模型 | SHOULD | 语义路由：规则/启发式分流，可配置映射 |
| 作为管理员，我希望相同请求不重复花钱 | SHOULD | 请求缓存：相同 prompt+参数 命中直接返回，记录 cached 标记 |
| 作为管理员，我希望预算超支自动降级 | SHOULD | 月度预算阈值，超限自动降级到便宜模型并告警 |
| 作为管理员，我希望看到优化效果 | SHOULD | 成本对比报表：路由前后同批请求成本差异 |

### Epic-7 安全防护（SHOULD）

| 用户故事 | 优先级 | 验收标准（AC） |
|---|---|---|
| 作为管理员，我希望拦截越狱/注入 | SHOULD | 低成本模型预检 or 规则检测，命中返回 400 |
| 作为管理员，我希望敏感信息脱敏 | SHOULD | 手机号/邮箱/身份证在转发与日志中掩码 |

### Epic-8 评测飞轮（COULD → 本期做 MVP）

| 用户故事 | 优先级 | 验收标准（AC） |
|---|---|---|
| 作为管理员，我希望自动积累评测样本 | COULD | 按模型/类型分层采样真实调用，生成数据集 |
| 作为管理员，我希望人工打标 | COULD | 后台对样本标记好/坏 |
| 作为管理员，我希望一键回归对比模型 | COULD | 同一批样本跑 A/B 模型，输出质量分 + 成本 + 延迟报告 |

## 4. 非功能需求（NFR）

| 类别 | 要求 |
|---|---|
| 性能 | ≥500 并发稳定；网关自身转发开销 P95 < 100ms；流式首字延迟低 |
| 可用性 | 演示环境可用性 ≥ 99%；网关无状态可水平扩容 |
| 安全 | Key 哈希存储；传输 HTTPS（本地 HTTP 可）；日志脱敏 |
| 数据 | 调用日志保留 ≥30 天；计费数据不丢失（对账兜底） |
| 可维护性 | 分层架构清晰；单测覆盖率核心模块 ≥ 60%；文档齐全 |
| 可移植性 | 全部 Docker 化，`docker compose up` 一键启动 |
