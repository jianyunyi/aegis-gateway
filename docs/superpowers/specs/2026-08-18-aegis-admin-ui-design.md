# AEGIS 管理后台 UI 重设计

## 设计读取

这是一个面向技术运营人员的 AI 网关管理后台重设计。目标是把现有默认 Ant Design 后台升级成更有识别度的 developer-ops 控制台：暖纸色工作区、墨黑侧栏、橙色品牌点和更有标题感的页面层级。

该方向采用 Editorial Console 视觉语言，但仍然服务后台效率，不做营销页式装饰。

- DESIGN_VARIANCE: 6
- MOTION_INTENSITY: 3
- VISUAL_DENSITY: 6
- 设计系统：继续使用 Ant Design 5
- 主题：暖纸色工作区 + 墨黑导航 + 橙色品牌强调

## 范围与约束

本次只优化核心业务后台页面：

- 仪表盘
- Key 管理
- 提供商
- 调用日志
- 账单
- 评测

保持不变：

- 登录页
- URL、页面信息架构和菜单名称
- 接口调用、请求参数、表单字段和数据行为
- 登录鉴权、登出和错误处理流程
- 现有 Ant Design 组件体系
- 现有加载、错误、空数据、弹窗、抽屉和表单校验行为

## 当前审计结论

现有后台已经具备完整业务能力，但视觉上仍有明显模板感：

- 侧栏是普通深蓝菜单，品牌记忆点弱。
- 工作区以浅灰蓝和白卡为主，卡片之间差异小，页面像默认后台皮肤。
- 顶部栏只承载登出，缺少产品化的状态和当前空间感。
- 页面标题、说明、工具条和表格之间的节奏还不够精致。
- 仪表盘四张统计卡同权重，关键指标没有主次。
- 表格页的卡片标题、工具条和表格边界过于常规。

本次不解决业务功能问题，只解决这些视觉和层级问题。

## 目标体验

用户进入后台后应能快速回答三个问题：

- 我现在在哪个模块。
- 系统当前状态如何。
- 下一步最重要操作是什么。

视觉上要从“普通后台模板”变成“有品牌感的运维控制台”。暖纸色提供温度，墨黑侧栏提供稳定性，橙色只用于品牌、主操作和关键提示。所有变化都应增强扫读，而不是制造装饰负担。

## 视觉系统

### 颜色

语义色通过 Ant Design `ConfigProvider` 统一配置，页面内减少散落硬编码。

- 工作区背景：暖纸色 `#f3efe6`
- 内容表面：浅纸白 `#fffaf1`
- 主导航：墨黑 `#20242a`
- 主强调：橙色 `#ff6b4a`
- 正文：近黑棕 `#24211d`
- 次级文字：温灰 `#6d6257`
- 边框：纸色边界 `#ded5c7`
- 成功、警告、错误继续保留 Ant Design 语义色，但需要调到与暖纸色背景协调。

橙色不能大面积铺满页面。它只用于品牌标记、主按钮、当前导航选中态和少量重点提示。

### 排版

- 继续使用系统无衬线字体，不引入新字体依赖。
- 页面标题增大并加重，形成 Editorial Console 的标题感。
- 数字、成本、Token、请求 ID 等数据可使用等宽字体，以提升运维场景的可读性。
- 表格正文保持标准后台字号，不牺牲密度。
- 不使用衬线字体，不使用营销页式大标题。

### 形状与层级

- 卡片、按钮、输入框和弹窗统一使用 8-12px 圆角。
- 不使用大圆角、玻璃拟态、渐变光斑或厚重阴影。
- 普通内容卡使用纸色表面 + 1px 暖灰边框。
- 关键指标卡允许使用墨黑底色，以打破四卡同权重。
- 表格用更轻的分隔线和更明确的 header 背景提高扫读性。

## 公共壳层

`SideLayout` 是本次最重要的改造点。

### 侧栏

- 背景从深蓝改为墨黑。
- 品牌区改为更强的 AEGIS 标识：橙色方形标记 + AEGIS + AI GATEWAY。
- 菜单仍保留现有中文标签和路由。
- 当前菜单项使用橙色背景或橙色强调，不只依赖文字颜色。
- 折叠状态保持可用，图标不溢出，不改变 Ant Design 响应式行为。

### 顶部栏

- 顶部栏从纯白改为融入暖纸色工作区。
- 左侧显示当前控制台上下文，例如 Gateway Control。
- 右侧保留后台身份文本和登出按钮。
- 登出行为不变。

### 内容区

- 背景使用暖纸色。
- 内容最大宽度维持宽屏友好，避免满屏铺散。
- 页面标题区统一为标题、说明和可选右侧状态块。
- 工具条统一为左侧说明、右侧操作。

## 页面设计

### 仪表盘

- 保留今日请求量、今日成本、今日 Token、成功率。
- 第一张关键指标卡使用墨黑底，其他指标使用浅纸白，形成主次。
- 统计数字使用等宽字体。
- 趋势图卡使用暖纸色边界和更清晰的标题区域。
- 数据来源文本降级，不抢标题注意力。
- 加载、错误和空趋势状态沿用现有行为。

### Key 管理

- 页面标题和说明保持不变。
- `Key 列表` 卡片改成纸色表面。
- 工具条保留总数和新建按钮。
- 新建 Key 按钮使用黑底或橙色主按钮，保证对比度。
- Key 前缀继续使用 code 样式，但需要与暖纸色背景协调。
- 明文 Key 提示仍然醒目，不降低安全提示层级。

### 提供商

- 保留提供商列表和新建提供商弹窗。
- Base URL code 样式保持可扫描。
- 启用状态标签保留语义色。
- 新建提供商按钮跟随统一主按钮样式。

### 调用日志

- 保留服务端分页和模型名筛选。
- 筛选输入框保持在工具条右侧，窄屏可换行。
- 表格 header 背景使用浅纸色层级。
- Request ID、成本、Token、延迟等数据使用更稳定的数字排版。
- 状态与缓存标签保持语义，不改含义。

### 账单

- 保留现有账单概览和明细行为。
- 成本数字和账单明细使用等宽数字排版。
- 卡片间距与其他页面统一。

### 评测

- 保留数据集、样本、运行报告的 Tabs、Modal、Drawer 和 API 行为。
- 数据集选择、主要动作和报告区域强化层级。
- 不改变评测表格字段和操作语义。
- 通过统一页头、卡片和工具条降低密集感。

## 动效与响应式

- 动效强度为 3，只使用 Ant Design 默认过渡、按钮 hover、active 反馈和加载状态。
- 不新增动画库。
- 不新增滚动监听。
- 宽表格继续横向滚动，不强行压缩列内容。
- 窄屏下页面标题、工具条和卡片改为单列。
- 折叠侧栏仍使用现有 Ant Design breakpoint。

## 可访问性与前端质量

- 按钮文字和背景必须满足清晰对比。
- 不使用白底白字、浅橙底白字等低对比组合。
- 焦点态、表单校验、弹窗键盘行为不回归。
- 不使用纯黑 `#000000` 或纯白 `#ffffff` 作为大面积主题色。
- 不在可见文案中使用装饰性长破折号。
- 页面不使用装饰性状态点，除非它表达真实状态。

## 验证策略

- 运行 `next lint`。
- 运行 `next build`。
- 检查核心路由仍可访问：`/dashboard`、`/keys`、`/providers`、`/logs`、`/billing`、`/evals`。
- 检查登录鉴权和登出行为不变。
- 检查桌面与窄屏下侧栏、页头、卡片、工具条和表格不重叠。
- 检查加载、错误、空数据、弹窗、抽屉和表单校验没有回归。

## 不做的事情

- 不改登录页视觉。
- 不改后端接口。
- 不改数据模型。
- 不改 URL、菜单标签、表单字段名或埋点意图。
- 不引入新的 UI 框架、字体或复杂动画依赖。
- 不做与 UI 重设计无关的业务重构。
