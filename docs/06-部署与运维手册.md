# 部署与运维手册 — AEGIS

> 版本：v0.1.0 ｜ 关联：章程 S6、PRD NFR、`deploy/` 目录

## 1. 构建指南

### 1.1 后端二进制（Linux，用于 Docker 镜像）

```bash
# 宿主机交叉编译（含网关与 mock 沙箱）
make build-linux
# 或直接：
cd backend
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -o bin/gateway-linux ./cmd/gateway
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -o bin/mockupstream-linux ./cmd/mockupstream
```

> 设计说明：本地/离线环境用"宿主机交叉编译 + alpine 运行时"（`deploy/Dockerfile.gateway`），
> 避免构建时联网拉 golang 镜像；CI（有网络）可直接跑 `go build` 并走多阶段构建。

### 1.2 前端（管理后台）

```bash
cd web
npm install        # 或 npm ci
npm run build      # 产物 .next/standalone（output: 'standalone'）
```

> Docker 镜像内执行 `npm ci`（走 npmmirror 镜像源），因为 node_modules 含平台相关二进制（next-swc），
> 不可复用宿主机安装的依赖。无网络环境请用 `npm run dev` 本地运行。

### 1.3 一键部署

```bash
./scripts/init-compose-env.sh                              # 生成本地随机密码与一次性管理员口令
make build-linux                                           # 先构建网关与 mock 二进制
docker compose --env-file .env -f deploy/docker-compose.yml up -d --build # MySQL/Redis → SQL 迁移 → 全栈
docker compose --env-file .env -f deploy/docker-compose.yml ps              # 状态
docker compose --env-file .env -f deploy/docker-compose.yml logs -f         # 日志
```

初始化脚本只创建一次 `.env` 和 `.secrets/`：秘密目录权限 0700，凭据文件权限 0600；仅 Redis 容器挂载的 `redis.conf` 为 0644，因为官方 Redis 镜像以非 root 身份读取配置，但宿主机其他用户仍不能遍历其父目录。两者均已加入 Git 忽略；`.env` 只存非敏感配置，Compose 通过只读 secret 文件挂载注入凭据。脚本只显示一次管理员密码；保存密码后再打开后台。为使非 root 网关进程读取本地文件秘密，Compose 使用初始化时的 `APP_UID`/`APP_GID` 运行网关与迁移服务。Compose 会自动运行独立 `migrate` 服务（只需 MySQL），网关只有在迁移成功后才启动；本地也可在 MySQL 已启动后运行 `make migrate`，它读取 `.secrets/mysql_dsn_host` 并使用 `127.0.0.1:3303`。

## 2. 服务清单与端口

| 服务 | 容器名 | 宿主机端口 | 说明 |
|---|---|---|---|
| MySQL | aegis-mysql | 127.0.0.1:3303 → 3306 | 数据卷持久化；网关使用专用非 root 用户 |
| Redis | aegis-redis | 127.0.0.1:6380 → 6379 | 密码认证，数据卷持久化 |
| 网关 | aegis-gateway | 127.0.0.1:8081 → 8080 | 宿主 loopback only；公网前必须接 HTTPS 反向代理 |
| mock 沙箱 | aegis-mockupstream | 127.0.0.1:8099 → 8099 | 演示用 OpenAI 兼容假上游 |
| 管理后台 | aegis-web | 127.0.0.1:3000 → 3000 | 通过 Next 同源 `/api` 反代访问网关 |

> 端口被占用时的处理：编辑 `deploy/docker-compose.yml` 端口映射（改宿主机侧即可，
> 容器内部端口不变，服务间仍走 compose 网络服务名）。

## 3. 配置项（环境变量）

| 变量 | 默认值 | 说明 |
|---|---|---|
| `APP_ENV` | dev | prod 时启用 gin release 模式 |
| `HTTP_ADDR` | :8081 | 网关监听地址 |
| `MYSQL_DSN` / `MYSQL_DSN_FILE` | 空（必须显式提供） | 敏感配置优先从 `MYSQL_DSN_FILE` 指定的文件读取；生产必须使用专用非 root 账号 |
| `REDIS_ADDR` | 127.0.0.1:6379 | Redis 地址（compose 内为 redis:6379） |
| `REDIS_PASSWORD` / `REDIS_PASSWORD_FILE` | 空（仅开发） | 生产必填；Compose 以 secret 文件强制 Redis 认证 |
| `JWT_SECRET` / `JWT_SECRET_FILE` | 仅开发有本地值 | 生产必填，至少 32 字节随机值；同时加密提供商 Key |
| `AUTO_MIGRATE` | dev=true / prod=false | GORM 只用于开发；生产禁用并执行版本化 SQL migrations |
| `SEED_DATA` | false | 默认关闭；开启且无管理员时必须提供引导用户名和至少 12 字节密码（建议用 `BOOTSTRAP_ADMIN_PASSWORD_FILE`），不创建演示 API Key |
| `PROMPT_CAPTURE_ENABLED` | false | 仅显式开启才存储脱敏 prompt；支持 `X-AEGIS-No-Prompt-Capture: true` 单请求退出 |
| `PROMPT_RETENTION_DAYS` | 30 | 每日清理过期 prompt 字段、采样样本和含逐样本文本的报告 |
| `MAX_REQUEST_BODY_BYTES` | 2097152 | 全局请求体上限，范围 1 KiB–16 MiB |
| `CORS_ALLOWED_ORIGINS` | 开发 localhost | 逗号分隔精确来源；不再反射任意 Origin |
| `BILLING_INTERVAL_MINUTES` | 5 | 计费对账定时任务间隔（0=禁用） |
| `CACHE_TTL_SECONDS` | 600 | 请求缓存 TTL |
| `UPSTREAM_TIMEOUT_SECONDS` | 180 | 上游调用超时 |
| `JWT_EXPIRE_MINUTES` | 720 | 管理端 JWT 有效期 |

管理员登录使用 Redis 固定 5 分钟窗口：每来源 IP 最多 10 次、同一 IP+规范化用户名最多 5 次、同一规范化用户名全局最多 30 次；限流键只保存身份值的 SHA-256 摘要，Redis 异常时 fail-closed。来源 IP 取网关的直接 TCP 对端，不信任任意 `X-Forwarded-For`/`X-Real-IP`。如果网关位于反向代理后，多个用户可能共享代理 IP 桶；上线前应确认代理拓扑和该限制的运维影响。

执行 `make migrate` 或 Compose 的一次性 `migrate` 服务，会按文件名在 `schema_migrations` 中记录并只运行未应用的 SQL 文件。迁移在固定 MySQL 会话中逐语句执行；`001` 是新库完整基线，`002` 补齐评测采样列，`003` 为旧库增加 API Key 账务列，`004` 增加 `usage_estimated` 标记。升级前仍应先备份。

prompt 内容默认不采集。显式开启采集时，会在写入前对常见邮箱、手机号、Bearer/API Key、密码/token 字段作规则脱敏；这不是任意个人信息识别保证，不能替代组织的数据授权或下游模型供应商审查。关闭采集后新请求不会写 `prompt_preview`/`prompt_for_eval`；老数据按保留期清理，采样接口也会被禁用。

## 4. 监控与可观测

- **调用级可观测**：每次请求的 usage 元数据写入 `usage_logs`（网关生成的 request_id、TTFT、路由方式、缓存标记、错误码）；prompt 除显式 opt-in 的脱敏采集外默认不保存
- **大盘**：管理后台仪表盘（今日请求/成本/Token/成功率/延迟）+ 7/30 天趋势
- **对账任务**：每 5 分钟聚合日账单 + Redis/MySQL 配额对账，日志 `billing reconcile done`
- **告警**：超预算请求返回 429 并记录 `budget_exceeded`；聊天请求可尝试降级至最便宜模型；预算 Redis 预留失败时 fail-closed 返回 503
- **可选扩展**：接入 Prometheus + Grafana（网关暴露 /metrics 为后续迭代项）

## 5. 备份与恢复

```bash
# MySQL 逻辑备份（建议 cron 每日）
docker compose --env-file .env -f deploy/docker-compose.yml exec -T --user 0 mysql sh -ec 'config=$(mktemp); trap "rm -f \"$config\"" EXIT; printf "[client]\nuser=root\npassword=%s\n" "$(cat /run/secrets/mysql_root_password)" > "$config"; chmod 600 "$config"; mysqldump --defaults-extra-file="$config" aegis' > backup/aegis-$(date +%F).sql

# Redis 持久化：AOF/RDB 在 redis-data 卷中，随容器生命周期保留

# 恢复
docker compose --env-file .env -f deploy/docker-compose.yml exec -T --user 0 mysql sh -ec 'config=$(mktemp); trap "rm -f \"$config\"" EXIT; printf "[client]\nuser=root\npassword=%s\n" "$(cat /run/secrets/mysql_root_password)" > "$config"; chmod 600 "$config"; mysql --defaults-extra-file="$config" aegis' < backup/aegis-2026-08-17.sql
```

## 6. 生产部署检查清单（安全）

见 [SECURITY.md](../SECURITY.md)「生产部署检查清单」：

- [ ] 为 MySQL root、MySQL 应用账号、Redis 和 `JWT_SECRET` 生成彼此独立的随机秘密；不要使用初始化脚本的本地开发凭据
- [ ] `AUTO_MIGRATE=false`；在应用启动前备份并运行版本化 SQL 迁移
- [ ] 仅经 HTTPS 反向代理/云 LB 发布 Web 和网关；将 `CORS_ALLOWED_ORIGINS` 限定为确切来源
- [ ] 保持 Redis 认证与 `RATE_LIMIT_FAIL_OPEN=false`，LB readiness 使用 `/readyz`
- [ ] 默认保持 `PROMPT_CAPTURE_ENABLED=false`；若有明确授权才开启，并设置合适的 `PROMPT_RETENTION_DAYS`
- [ ] 不把规则脱敏视为完整 PII 检测；确认对候选模型与 judge 的数据传输符合组织授权和供应商条款
- [ ] 配置 `MAX_REQUEST_BODY_BYTES`；管理员登录按 IP、账号及 IP+账号联合限流

## 8. Cloudflare 上线（实测通过）

### 8.1 前端：Cloudflare Pages（推荐，TTFB 最优）

静态导出部署到 Pages，HTML/JS 由**边缘节点直接服务**，不依赖隧道与本机在线：

```bash
cd web
# 1. 静态导出构建（next.config 双模式：NEXT_OUTPUT=export 时输出 out/）
$env:NEXT_OUTPUT='export'; npm run build

# 2. 部署（首次创建项目 + 登录 wrangler）
npx wrangler pages project create aegis-admin --production-branch main
npx wrangler pages deploy out --project-name aegis-admin --branch main
# 得到 https://aegis-admin-xxxx.pages.dev（CI 可自动化部署）
```

- 页面 JS 若直连公网网关域名（浏览器侧），需将 Pages 域名精确加入 `CORS_ALLOWED_ORIGINS`；优先通过同源 `/api` 反向代理
- 静态资源带 `immutable` 缓存头，Cloudflare 自动边缘缓存
- 实测：本地服务端 TTFB 12ms；公网 TTFB 受"本机→边缘"网络 RTT/丢包主导（网络差时 TLS 握手可达 2s+）；Pages 使 HTML 不再回源本机，网络稳定时显著优于隧道

### 8.2 网关：Cloudflare Tunnel

架构：**Cloudflare 边缘（HTTPS/CDN/WAF）+ Tunnel 穿透本机**，网关/数据库不暴露公网。

```bash
# 1. 安装 cloudflared 并登录（浏览器授权选择域名）
cloudflared tunnel login

# 2. 创建隧道
cloudflared tunnel create aegis

# 3. 配置入口（%USERPROFILE%\.cloudflared\config.yml）
#    tunnel: <tunnel-id>
#    ingress:
#      - hostname: 0001.indevs.in        → http://localhost:3000（管理后台）
#      - hostname: aegis-api.0001.indevs.in → http://localhost:8081（网关）
#      - service: http_status:404

# 4. 绑定 DNS（CNAME → <tunnel-id>.cfargotunnel.com）
cloudflared tunnel route dns aegis 0001.indevs.in
cloudflared tunnel route dns aegis aegis-api.0001.indevs.in

# 5. 启动（建议注册为系统服务：cloudflared service install）
cloudflared tunnel run aegis

# 6. 验证
curl https://aegis-api.0001.indevs.in/healthz
```

上线配套（已实测）：
- 管理后台构建时 `NEXT_PUBLIC_API_BASE` 指向公网网关域名（见 deploy/Dockerfile.web）
- 根目录 `.env` 只含非敏感配置；MySQL、Redis、JWT 和引导密码通过只读 secret 文件注入 Compose（均不入库）。部署启动默认关闭 `SEED_DATA`，首个管理员通过显式引导凭据建立
- **注意**：JWT_SECRET 同时是提供商 Key 的 AES 加密密钥，修改后需用新值重加密 `providers.api_key_enc`（部署工具见 `.cache/gentool`，不入库）

## 10. 多实例验收与故障策略

- `/healthz` 仅检查进程存活；`/readyz` 检查 MySQL、Redis，依赖异常或进程开始退出时返回 503。LB/Kubernetes readiness 使用 `/readyz`，liveness 使用 `/healthz`。
- `UPSTREAM_TIMEOUT_SECONDS` 按秒解析，默认 180 秒；`BILLING_INTERVAL_MINUTES=0` 禁用定时对账，负数/非法值回退默认 5 分钟。
- `RATE_LIMIT_FAIL_OPEN=false` 为默认：Redis 限流失败返回 503；显式设置 true 才放行，两种模式均记录 `rate_limit_dependency_error`。`RATE_LIMIT_TIMEOUT_MS` 默认 500，`READINESS_TIMEOUT_MS` 默认 1000。
- 限流 Lua 键使用共同 hash tag。现有 Redis 客户端仍是单节点客户端；hash tag 不等于已经支持 Redis Cluster 客户端拓扑。
- 账单聚合使用同一 MySQL 会话的命名锁及唯一键 upsert；未取得锁的本次聚合跳过。该机制要求所有实例共用同一 MySQL 主库，不适用于独立主库。
- 用量流水与 MySQL 配额增量在单个事务提交。三种代理端点都会先通过 Redis Lua 原子预留输入估算量及显式 `max_tokens`，Redis 故障 fail-closed；提交后释放预留并投影 MySQL 已用量。响应 usage 可能高于估算（特别是没有给出 `max_tokens` 时），此时实际用量仍入账，后续请求按 MySQL 已用量阻止。进程崩溃留下的预留最多保留 10 分钟；上游已消费但 MySQL 事务不可用仍需监控和人工对账。
- `X-Request-ID` 始终由网关生成随机 128 位 ID；不信任调用方提供值，避免重放/重复 ID 覆盖唯一账务流水。
- `usage_logs.status=0` 表示成功；客户端取消为 499，流式缺少 `[DONE]` 为 502 / `upstream_stream_incomplete`。SSE 已发送的 HTTP 200 无法事后改变，访问日志 `result` 与流水记录实际终态。TTFT 从首个内容或工具调用 delta 起算。

CI 的 `enterprise-integration` 使用 MySQL 8.0 + Redis 7，启动两个独立 HTTP 网关实例，并通过 TCP 故障门切断已有连接及新连接。测试共享限流、fail-open/closed、readiness 故障恢复与 draining、并发用量/对账、流式取消/截断/首字时间及实际秒级超时。
