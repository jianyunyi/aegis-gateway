| 字段 | 内容 |
|---|---|

| 仓库名 | `aegis-gateway` |
| 一句话定位 | 统一的企业大模型接入网关：路由、限流、计费、观测、评测一站式平台 |
| 干系人 | 本人（唯一，兼任产品 / 研发 / 测试 / 运维）；AI 协作者（架构与研发指导） |

---

## 1. 背景与动机

多业务线接入多家大模型（OpenAI / DeepSeek / 通义 / 本地模型）时存在以下真实痛点：

1. **重复接入**：每个业务各自接 SDK、各自管理 Key，改模型要改代码。
2. **成本不可控**：没有统一限流与配额，没有预算概念，月底账单爆炸才知道超支。
3. **不可观测**：调用失败、慢、贵，完全没有调用级日志可以查。
4. **不可评测**：换模型全凭感觉，没有量化数据支撑"该不该换 Claude"这类决策。

AEGIS 以"企业大模型基础设施"的视角解决上述问题，同时作为面试项目的差异化亮点（做 AI 的基础设施层，而非烂大街的消费 AI 应用层）。

## 2. 业务目标（SMART）

| 编号 | 目标 | 度量 |
|---|---|---|
| B1 | 统一接入 | 任意 OpenAI SDK 仅改 base_url 即完成接入，零代码改造 |
| B2 | 降本 | 同业务量 API 成本下降 ≥ 30%（语义路由 + 缓存 + 降级） |
| B3 | 可控 | 每 Key 限流与配额、月度预算、防滥用、防盗刷 |
| B4 | 可观测 | 全量调用日志 + 延迟/成本/成功率实时大盘 |
| B5 | 可评测 | 自动采样建评测集，一键回归对比模型效果与成本 |
| B6 | 可面试 | 每个模块能深讲 30 分钟，沉淀 ≥5 个 ADR + 2 篇技术文章 |

## 3. 成功标准（验收口径）

- **S1** 用官方 OpenAI SDK（Go/Python/JS 任一）改 base_url 即可完成对话与流式调用。
- **S2** 网关压测 ≥500 并发稳定，网关自身转发开销 P95 < 100ms（不含上游耗时）。
- **S3** 管理后台可查任意一次调用的 token / 成本 / 延迟 / 模型 / 状态。
- **S4** 可演示成本优化：同一批请求路由后成本对比报表。
- **S5** 评测流程可演示：采样 → 打标 → 跑回归 → 出对比报告。
- **S6** `docker compose up` 一键启动全栈（网关 + 后台 + MySQL + Redis）。

## 4. 范围

### 4.1 In-scope（本期必须做）

- OpenAI 兼容代理（`/v1/chat/completions`、`/v1/completions`、`/v1/embeddings`、`/v1/models`），支持 SSE 流式
- API Key 管理（生成 / 轮换 / 吊销 / 配额），Key 只存哈希
- 限流防滥用（Redis 令牌桶 + 滑动窗口）
- 计费（按 token 计价）、日账单、对账
- 管理后台（Next.js + React + TS）：大盘 / Key / 提供商 / 模型 / 日志 / 账单 / 评测
- 成本优化三件套：语义路由、请求缓存、预算自动降级
- 安全中间件：鉴权、越狱/注入检测（低成本）、敏感信息脱敏
- 评测飞轮：自动采样、人工打标、模型回归对比
- 可观测：Prometheus 指标 + Grafana（或轻量自绘图表）

### 4.2 Out-of-scope（明确不做，防止范围蔓延）

- 模型训练 / 微调 / 蒸馏
- RAG 与向量数据库（那是知识库项目的活）
- 面向终端用户的聊天产品 UI（AEGIS 是基础设施，不是 C 端产品）
- 多租户组织 / RBAC 权限体系（单用户演示，接口预留）
- K8s / 消息队列（时间允许则后置，不在本期承诺）

| 里程碑 | 周期 | 交付物 | 演示点 / 验收 |
|---|---|---|---|
| M1 立项与设计 | W1-2 | 文档四件套（章程/PRD/TDD/规范）+ 工程骨架 | 编译通过、`/healthz` 返回 OK |
| M2 核心代理 | W3-4 | 代理链路 + Key 管理 + 限流 | curl 完成流式对话，错误 Key 被拒 |
| M3 计费与观测 | W5-6 | 计费 + 调用日志 + 管理后台大盘 | 后台实时看到调用记录与费用 |
| M4 成本优化 | W7-8 | 语义路由 + 缓存 + 预算降级 | 成本对比报表（降本 ≥30%） |
| M5 评测与工程化 | W9-10 | 评测飞轮 + 测试 + CI + 部署 + 文档沉淀 | docker compose 一键上线演示 |

## 6. 风险登记册（Risk Register）

| ID | 风险 | 影响 | 概率 | 缓解措施 |
|---|---|---|---|---|
| R1 | API 预算超支 | 高 | 中 | 限流 / 配额 / 预算降级 / Ollama 本地兜底 |
| R2 | 范围蔓延导致延期 | 高 | 高 | MoSCoW 硬优先级；每期固定演示点；Out-of-scope 硬约束 |
| R3 | 上游模型服务不稳定或接口变更 | 中 | 中 | 多提供商冗余、故障切换、超时与重试 |
| R4 | 面试讲不深 | 高 | 中 | 关键决策全部写 ADR；每模块准备追问清单 |
| R5 | 本地环境不一致 | 低 | 高 | Docker 统一环境；README 一键启动 |
| R6 | 日志含敏感数据 | 中 | 中 | 脱敏中间件；Key 只存哈希；日志脱敏后落库 |
