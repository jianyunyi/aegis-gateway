# 开发规范 — AEGIS

> 版本 v0.1，自 M1 起生效。所有提交与代码评审以本规范为准。

## 1. Git 工作流（GitHub Flow 简化版）

- 主干分支 `main`：**始终保持可编译、可运行**
- 功能分支：`feat/<模块>-<简述>`，如 `feat/proxy-stream`
- 修复分支：`fix/<简述>`，文档分支：`docs/<简述>`
- 每个功能合入前必须评审（本地自评也走同一 Checklist）
- 禁止直接向 main 提交（紧急热修复除外，须注明原因）

## 2. 提交规范（Conventional Commits）

格式：`<type>(<scope>): <subject>`

- type：`feat / fix / docs / test / chore / refactor / perf`
- scope 示例：`proxy / billing / web / deploy / eval`
- 示例：`feat(proxy): 实现 OpenAI 兼容流式转发`
- 一条提交只做一件事；正文写清"为什么"，不止"做了什么"

## 3. Go 编码规范

### 3.1 分层与依赖方向

```
handler → service → repository → model
middleware 只依赖 repository / model
```
禁止：handler 直接写 SQL；跨层反向调用；service 依赖 handler。

### 3.2 错误处理

- 错误必须向上包装：`fmt.Errorf("...: %w", err)`
- 业务错误统一错误码（见第 5 节），由 handler 层转换为响应
- 不吞错误；确需忽略时注释原因

### 3.3 日志

- 标准库 `log/slog`，JSON 格式，结构化字段
- 每个请求贯穿 `request_id`（middleware 注入）
- 禁止 `fmt.Println` 调试残留

### 3.4 配置

- 12-Factor：环境变量 + `.env`；统一走 `internal/config`，禁止散落 `os.Getenv`

### 3.5 命名与风格

- 包名小写单数；导出标识符必须有注释
- 提交前过 `gofmt -l` 与 `go vet`

### 3.6 测试

- table-driven 单测，命名 `TestXxx`
- 核心模块（proxy / router / billing）覆盖率 ≥ 60%

## 4. TypeScript / React 规范

- `tsconfig strict`；类型集中在 `lib/types.ts`，与后端契约对齐
- API 调用统一走 `lib/api.ts`（拦截器统一处理认证与错误）
- 页面组件只做组合；业务逻辑抽到 hook 或 lib
- ESLint（next/core-web-vitals）；禁止 `any` 泄漏（必要时注释理由）

## 5. 统一错误码

| code | 含义 | HTTP |
|---|---|---|
| 0 | 成功 | 200 |
| 40001 | 参数错误 | 400 |
| 40101 | 未认证（JWT 无效） | 401 |
| 40102 | API Key 无效 | 401 |
| 40103 | API Key 已禁用/过期 | 401 |
| 40301 | 无权限 | 403 |
| 42901 | 触发限流 | 429 |
| 42902 | 配额不足 | 429 |
| 50001 | 内部错误 | 500 |
| 50201 | 上游模型错误 | 502 |

代理侧（OpenAI 协议）错误沿用 `{"error": {"message", "type"}}` 格式。

## 6. 代码评审 Checklist

**功能**
- [ ] 符合 PRD 验收标准；需求有变更是否回写 PRD
- [ ] 边界与异常（空、超时、上游失败、并发）已处理
- [ ] 流式路径无全量缓冲（ADR-003）

**质量**
- [ ] 分层符合规范，无跨层调用
- [ ] 错误码 / 日志字段符合规范
- [ ] 数据库访问走 GORM，无 SQL 拼接注入风险
- [ ] 敏感信息（Key / 上游 Key）不落日志

**测试**
- [ ] 核心逻辑有单测；行为变更更新既有用例

**安全**
- [ ] 输入校验 / 脱敏位置正确
- [ ] 限流 / 配额对恶意请求有兜底

**性能**
- [ ] 无 N+1 查询；热点路径有索引
- [ ] Redis 用原子脚本而非"读-改-写"

## 7. 完成定义（Definition of Done）

- [ ] 代码可编译，单测通过
- [ ] 有对应文档 / 注释（接口契约或 ADR 引用）
- [ ] 本地 `docker compose` 可跑通当期演示点
- [ ] 无遗留 TODO（有则登记到待办清单，不静默遗留）
