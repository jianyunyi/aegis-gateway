# Aegis Gateway 上线入口与数据库演练

这份手册把管理后台入口、手工评测样本保留和数据库演练串成可执行流程。**以下配置和脚本只用于部署前的本地/隔离环境；本次改动不会连接生产，也不会替你部署、合并或清理现有样本。**

## 1. 后台入口：公网只开放 API

推荐让 Aegis 管理页面和登录 API 只经 Tailscale tailnet 访问。仓库提供可选 Compose 覆盖文件 [`deploy/docker-compose.admin-vpn.yml`](../deploy/docker-compose.admin-vpn.yml)、Tailscale Serve HTTPS 配置 [`deploy/admin-vpn/serve.json`](../deploy/admin-vpn/serve.json) 和公网 API 专用 Caddy 示例 [`deploy/Caddyfile.aegis-api.example`](../deploy/Caddyfile.aegis-api.example)。

先在 tailnet 管理策略中定义管理员组、后台节点标签，并只允许该组访问该标签的 TCP 443；将示例合并到现有策略，而不是覆盖整份策略：

```json
{
  "groups": {
    "group:aegis-admins": ["admin@example.com"]
  },
  "tagOwners": {
    "tag:aegis-admin": ["autogroup:admin"]
  },
  "grants": [
    {
      "src": ["group:aegis-admins"],
      "dst": ["tag:aegis-admin"],
      "ip": ["tcp:443"]
    }
  ]
}
```

为 `tag:aegis-admin` 创建受限的 Tailscale 认证密钥，存入仓库忽略的本地 `.secrets/tailscale_authkey`，并设置权限 `0600`。tailnet 身份提供方应强制 MFA，并按组织要求启用设备审批。不要把密钥提交到仓库、写入 `.env` 或贴到聊天中。启动覆盖配置时，密钥仅由 shell 读入 Compose：

```bash
chmod 600 .secrets/tailscale_authkey
TS_AUTHKEY="$(cat .secrets/tailscale_authkey)" docker compose \
  --env-file .env \
  -f deploy/docker-compose.yml \
  -f deploy/docker-compose.admin-vpn.yml \
  up -d --build
```

Compose 会把 `web` 和 Tailscale sidecar 放在同一网络命名空间，Tailscale Serve 只代理到 `127.0.0.1:3000`；`AllowFunnel` 显式为 `false`，不允许把 Serve 发布成 Funnel。Tailscale 状态保存在独立卷中，重启后继续使用已注册节点。请在 tailnet 中启用 MagicDNS 和 HTTPS certificates，并把 `TAILSCALE_IMAGE` 固定为组织已验证的版本/镜像摘要；保护 Docker 管理权限，因为能访问 Docker daemon 的人可以读取容器环境。Tailscale 的容器参数和 Serve 配置参考[官方 Docker 参数文档](https://tailscale.com/docs/features/containers/docker/docker-params)、[容器网络示例](https://tailscale.com/docs/features/containers/docker/how-to/connect-docker-container)及 [Serve 文档](https://tailscale.com/docs/features/tailscale-serve)。

公网 HTTPS 反向代理只应加载 Caddy 示例中的 API 主机：`/v1` 和 `/v1/*` 反代到宿主机 loopback 上的 `127.0.0.1:8081`，其他路径默认 404。**不要把管理页面、`/login` 或 `/api/v1/admin/*` 加入公网路由。**若组织因业务需要采用公网后台入口，必须在边缘同时保护页面和登录 API，使用 MFA 与 IP allowlist，并配置 WAF 与失败登录告警；WAF/限速不能代替 MFA。本仓库不伪造组织的 IdP/MFA 配置。

`docker-compose.yml` 中 Gateway、Web、Redis、MySQL 仍绑定宿主机 loopback；防火墙也应阻止公网直连这些端口。WAF 用于公网 API 的扫描拦截和限速，不作为后台访问控制。

### 入口验收

从**不在 tailnet/VPN 内**的电脑或手机网络运行一次：

```bash
PUBLIC_API_URL=https://api.example.com \
ADMIN_URL=https://aegis-admin.example.ts.net \
scripts/verify-admin-access.sh outside
```

验收脚本要求公网 `/v1/models` 可到达并返回认证拒绝（401/403），公网 `/api/v1/admin/auth/login` 和 `/login` 都是 404，Tailscale 管理地址则无法访问或返回明确拒绝（000/403/404）。然后连接 tailnet，从其中一台获准设备运行：

```bash
PUBLIC_API_URL=https://api.example.com \
ADMIN_URL=https://aegis-admin.example.ts.net \
scripts/verify-admin-access.sh inside
```

后台登录页应返回 200；随后由操作人员手动登录并确认管理页和登录 API 正常。记录执行地点、时间、结果和 tailnet ACL 版本。**不得只在 VPN 内验证；外网拒绝是上线门槛。**

## 2. 评测样本：只收合成/彻底去标识内容

生产 `PROMPT_CAPTURE_ENABLED=false` 继续保持强制关闭。手工录入样本也只能是合成内容或彻底去标识的数据；仅删除姓名不等于去标识。新手工样本创建时，页面和 API 都要求明确确认，数据库记录确认时间和创建后 30 天的到期时间；新建日志采样样本也写入 30 天到期时间。每日清理只删除到期时间明确且已到期的新样本。

新样本可通过管理页面的“删除”确认，或 JWT 保护的 `DELETE /api/v1/admin/evals/samples/{id}` 逐条删除。删除会清除匹配样本的已保存报告文本，同时保留不含文本的汇总分数；该操作不可撤销。所有历史无到期字段的样本（不论手工或日志采样来源）在页面禁用直接删除，API 返回 409；它们只能经下方的隔离盘点/备份/逐 ID 工具删除。API 不支持批量删除。

迁移 `005_eval_sample_retention` **不会给任何历史样本自动填入到期时间**。这些行会以 `expires_at = NULL` 保留，不会被每日清理任务或后台逐条删除接口自动处理。先在恢复到隔离库的副本上盘点并确认保留/清理范围，再为每条删除制作私有备份并逐条确认。

## 3. 生产备份只能恢复到隔离数据库

演练需要一份由用户/运维提供的生产备份文件。准备一个只监听 `127.0.0.1` 的独立 MySQL 8 实例、仅用于演练的账号和 Redis；不要把生产 DSN、生产 secret 或任何连接生产网络的凭据放入演练文件。演练 schema 名必须是 `aegis_rehearsal` 或 `aegis_rehearsal_YYYYMMDD_<6-12位小写随机十六进制>`。工具会拒绝远程 MySQL、socket、其他 schema 名和权限过宽的 DSN 文件。

先在本机为隔离实例创建空 schema 和专用账号，然后在仓库外安全传递的秘密文件中写入演练 DSN：

```bash
umask 077
install -d -m 700 .secrets
# 将下面模板中的用户、密码、schema 替换为仅供本地演练的值；文件不得提交。
printf '%s\n' 'rehearsal_user:LOCAL_ONLY_PASSWORD@tcp(127.0.0.1:3306)/aegis_rehearsal_20261102_a1b2c3?parseTime=true&loc=UTC' > .secrets/rehearsal_dsn
chmod 600 .secrets/rehearsal_dsn
export AEGIS_REHEARSAL_DSN_FILE="$PWD/.secrets/rehearsal_dsn"
```

依次执行：

```bash
# 1. 只把备份恢复进空的本机 aegis_rehearsal* schema；不会连接或改写源生产库。
scripts/db-rehearsal.sh restore --from /secure/offline/aegis-production-backup.sql

# 2. 先盘点所有样本元数据；输出不包含 prompt/reference 内容。
scripts/eval-samples.sh inventory

# 3. 将迁移前 schema 版本、关键表行数和记录指纹保存成私有基线。
scripts/db-rehearsal.sh status --out .secrets/baseline-before.json

# 4. 备份隔离副本；备份文件以 0600 新建，并打印 SHA-256。
scripts/db-rehearsal.sh backup --out .secrets/before-migration.sql

# 5. 在隔离副本应用此 checkout 的版本化 SQL migration，并核对数据未变、schema 已升级。
scripts/db-rehearsal.sh migrate
scripts/db-rehearsal.sh verify --baseline .secrets/baseline-before.json
```

盘点输出只显示样本 ID、数据集、来源、创建时间、到期时间和是否有策略确认记录，不会导出样本文本。确认哪些旧样本应保留/删除、确认期限之后，才可按 ID 删除。每条删除前工具会自动制作新的完整隔离库备份，要求 `--confirm-id` 与 ID 一致，并在终端输入精确的 `DELETE <ID>`；不提供批量清理模式：

```bash
scripts/eval-samples.sh delete --id 123 --confirm-id 123 \
  --backup-before-delete .secrets/before-delete-123.sql
```

备份可能包含敏感内容，只能放在受限并加密的存储中，按组织的备份期限销毁。工具要求 mysqldump/mysql 客户端已安装，恢复目标必须为空，拒绝备份头部的 `CREATE/DROP DATABASE` 和 `USE` 语句。`status` 的样本文本指纹由 MySQL `SHA2` 计算；清单只保存摘要，不把 prompt 内容写入输出。

## 4. API/配额检查与应用回滚验证

先在候选应用连到的隔离库上检查管理登录、关键 Key/Provider/Model 记录、readiness 和公开 API 路径。应用演练仍必须设置 `APP_ENV=prod`、`AUTO_MIGRATE=false`、`PROMPT_CAPTURE_ENABLED=false`，并连接隔离 Redis。再用隔离环境中的测试 Key 和本地 mock upstream 完成一次 API 请求，核对 `usage_logs` 和 Key 已用 token/配额；重复请求直到超过专门设置的测试限额，确认网关返回 429。不要在生产 Key、生产上游或真实客户请求上做配额试验。

本仓库可运行的自动化检查：

```bash
cd backend
go test ./... -race -count=1
go vet ./...
TEST_MYSQL_DSN='仅指向本地隔离 MySQL 的管理 DSN' go test -tags=integration ./...
```

集成测试会创建并删除测试 schema；`TEST_MYSQL_DSN` 只能指向本地隔离 MySQL，不能指向生产服务器。数据库工具的 `verify` 会比较迁移前后的关键表行数和指纹，并检查关键新旧字段及 `005_eval_sample_retention` 版本记录。

### 分开验证数据库恢复和应用回滚

**数据库恢复：**把迁移前备份恢复到另一个全新的本机 `aegis_rehearsal_...` schema，然后以新的 mode-0600 DSN 运行：

```bash
AEGIS_REHEARSAL_DSN_FILE="$PWD/.secrets/recovery_dsn" \
  scripts/db-rehearsal.sh restore --from .secrets/before-migration.sql
AEGIS_REHEARSAL_DSN_FILE="$PWD/.secrets/recovery_dsn" \
  scripts/db-rehearsal.sh verify --baseline .secrets/baseline-before.json --allow-database-diff --pre-migration
```

通过条件是清单中的每张表行数/指纹与迁移前基线一致。这个恢复必须落到另一个隔离 schema，不得覆盖迁移后的副本，更不得恢复到生产。

**应用回滚：**保存部署时的上一版镜像 digest 和配置；把上一版应用镜像临时指向已迁移的隔离副本及隔离 Redis，保持 `PROMPT_CAPTURE_ENABLED=false`，检查 `/readyz`、管理登录、Key/配额读写及 API 冒烟流程。以下脚本自动验证上一版 Gateway 的启动、数据库/Redis readiness 和公开 API 路由拒绝：

```bash
PREVIOUS_GATEWAY_IMAGE='aegis-gateway:previous-version' \
AEGIS_REHEARSAL_DSN_FILE="$PWD/.secrets/rehearsal_dsn" \
REHEARSAL_REDIS_PASSWORD_FILE="$PWD/.secrets/rehearsal_redis_password" \
REHEARSAL_JWT_SECRET_FILE="$PWD/.secrets/rehearsal_jwt_secret" \
REHEARSAL_REDIS_ADDR=127.0.0.1:6380 \
scripts/verify-gateway-rollback.sh
```

只在 Linux 隔离主机运行，预先将专用 Redis 绑定到 loopback；脚本会先用数据库工具验证 DSN 只指向本机 `aegis_rehearsal*` schema，拒绝拉取镜像，要求秘密文件为 mode `0600`，并以非 root、read-only 容器只绑定 `127.0.0.1:18080`。若发布同时改变 Web 镜像，还须以相同隔离流程启动并验收已记录的上一版 Web 镜像。不要把生产 secret、生产卷或生产流量接入此演练。只有数据库恢复和旧应用镜像验证都通过，才可由运维另行安排正式生产维护窗口；MySQL DDL 不尝试反向执行，数据库回退使用迁移前备份恢复到经批准的目标。

## 5. 当前边界

此 checkout 仅实现配置、工具、测试和文档。没有生产数据库连接、生产备份文件或本地 Docker daemon；因此**没有执行真实生产副本恢复、数据库迁移、API/配额 smoke、实际样本删除或应用镜像回滚**。只有在运维提供备份并在隔离环境完成上述步骤后，才能记录这些演练为通过。
